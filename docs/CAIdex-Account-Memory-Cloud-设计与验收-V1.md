# CAIdex Account、Memory 与 Cloud：设计与验收 V1

正式产品决定：2026-10-08。状态：**设计已确定，尚未实现或运行验收**。本文补充 [实施计划 V3](CAIdex-实施计划-V3.md) 与 [UI 规范](CAIdex-UI-规范-V1.md)，不改变现有 F/G → H → I → Windows → iOS → CLI → Relay → R 主线；L SSH Remote 仍按 V3 位于 Windows 与 iOS 之间。原 V2 仅作需求背景；账户、数据库、记忆和云同步冲突处以本文及更新后的 V3/UI 为准。

## 1. 目标、非目标与当前事实

正式目标是同一 CAIdex 账户跨受支持客户端使用 Chat、个人/项目长期记忆及授权云同步。账户由 CAIdex 官方统一运营，普通用户不需要部署身份服务器，Windows/iOS直接提供注册；CLI只登录已有账户，不提供注册或邮箱验证开户入口。每人拥有不可变的唯一 `user_id`，邮箱只是可变登录身份；换邮箱、电脑或模型不改变记忆归属。

本次仅固化设计、实施顺序和验收条件，不建立账户服务器、数据库、迁移脚本、Memory Engine、邮件系统或 GUI。现有已验证范围仍是固定 Codex Runtime、凭据 Broker、ModelProvider/Gateway 和逐 Provider 离线适配；具体证据见 [HANDOFF](../HANDOFF.md)。账户、生产 Host、普通 Chat、云同步和客户端页面均不得因此标记为已完成。

不重新训练基础模型，不另造 Agent 或模型 HTTP 框架，不将云端改造成 Codex 执行器，不强制绑定设备，不部署异地备份。现有 Provider 的能力门槛、经典/Lite 适配和 Runtime 审批保持不变。

## 2. 系统职责与信任边界

| 系统 | 正式职责 | 边界 |
| --- | --- | --- |
| Windows / iOS 客户端 | 原生账户流程、按账户隔离的 SQLite 缓存、Chat/记忆设置、outbox/cursor、同步与用户纠错/导出；共享 Rust 核心供 Tauri/UniFFI 使用 | 未登录或云端故障时，已配置的本地 Codex、文件和本地模型按既有权限继续工作；云端数据访问必须认证 |
| Windows / Linux CLI | 英文账户登录/退出/会话状态；按OS用户/账户/项目隔离的SQLite本地记忆与同步缓存；共享核心与Host操作 | 不注册；未登录可用已配置本地能力；账户认证不授予Host权限；完整TUI/exec及命令见[CLI规范](CAIdex-CLI-完整交互与验收规范-V1.md)（待实现） |
| 用户授权的 Codex Host | 真实 Runtime 生命周期、执行/审批/事件恢复；SQLite journal；用自身 Broker 中的模型凭据 | SSH/Relay 配对和 Host ACL 单独授权；账户登录不授予 Shell、文件系统、管理员权限或其他电脑的 Key |
| CAIdex 官方云端应用服务 | 认证、会话/安全、Chat 与记忆同步 API、授权检索、记忆作业状态编排、EmailSender、数据删除与备份管理 | 不编排Host执行任务、不执行项目工具、不持有用户模型 API Key、不接管 Runtime 线程；HTTPS 服务端是信任边界，不宣称历史/记忆端到端加密 |
| 云端 PostgreSQL + pgvector | 账户、Chat、长期记忆、版本/来源、权限、同步事件与相关服务数据 | 从正式服务第一版采用 PostgreSQL；不先做 SQLite 云端服务再迁移 |
| 已有 ModelProvider / Gateway | Chat、记忆整合及 Embedding 的模型能力/调用接入；Gateway 继续仅适配 Responses | 复用既有传输与凭据机制；Embedding 若当前接口尚不能表达，在 I 内验证必要契约扩展，不能伪装已有支持或新建第二套传输 |
| 邮件供应商 | 发送事务邮件 | 只得到发送所需最少资料；邮件 API Key 只在服务端安全配置 |

三个身份域必须分开：**账户会话身份、执行端凭据 owner、Host 配对/执行权限**。现有 `CredentialRef.owner` 是执行端持久 ID，不改解释为 `user_id`；Gateway 的本地随机 Bearer 也不是账户令牌。未来 I 的账户缓存/配置 ACL 是新增的授权维度，不能把已有本地 Broker 检查当成多用户账户隔离已经完成。参见 [凭据设计](CAIdex-Credentials-设计与验收.md) 与 [Gateway 设计](CAIdex-Model-Gateway-设计与验收.md)。

开发 VPS `/root/projects/CAIdex-v1.0` 继续编译、Provider 测试及 Runtime 工作；官方云端早期内测使用另有的中国大陆 2 核 / 2 GB / 50 GB VPS。用户自有远程执行 Host、开发 VPS 和统一云服务是不同职责，不能因“VPS”一词将其混同。废弃目录 `/root/projects/CAIdex` 不作当前依据。

## 3. 用户流程与客户端入口

1. 未登录可使用已配置的本地能力。Windows 首次启动可展示欢迎页；主界面右上角提供“登录 / 注册”，侧边栏底部有账户入口。iOS 在合适的顶部提供注册入口，以 SwiftUI 原生注册/登录/恢复流程接入。登录、注册可相互切换；不要求外部网站预注册。
2. 邮箱注册 → 验证邮箱 → 建立账户会话；邮箱密码、Passkey 都属于首版正式认证范围。登录后 Windows 顶部未登录按钮消失；两平台侧边栏底部显示头像、昵称和账户菜单。GUI 默认简体中文、可选英文；CLI的账户入口与文案保持英文，只登录Windows/iOS已注册账户；无register/signup。
3. 设置“账户与安全”管理资料、邮箱、认证方式、已登录设备、退出其他设备、恢复与注销。每台新设备直接登录，不需要旧设备批准，默认不限制数量。
4. 设置“记忆与个性化”管理自动记忆、**同步记忆（新账户默认关闭）**、个人/项目记忆、整合模型与 Provider 使用权限；设置“云同步”独立管理 Chat 历史及展示同步状态。Windows/iOS/CLI登录自动继承账户现有Enabled/Disabled与版本/epoch，不能重置为设备默认；继承Enabled不等于上传此设备匿名/其他账户/未授权历史资料，登录本身不是这类上传授权。
5. 首次开启记忆同步须已登录，并确认上传哪些个人/项目记忆及来源资料；同步范围内也须符合项目权限与隐私限制。默认未选择的本地数据不上传。
6. 关闭曾开启的记忆同步时明确选择 A“仅停止同步，保留此前云端记忆”或 B“停止同步并删除云端记忆”；B 显示本机保存情况、其他设备/队列影响和备份保留限制，确认保留哪些本地副本并重新认证。
7. 退出或切换账户前展示未同步 Chat/记忆及待确认关闭/删除操作，允许明确选择按原账户隔离保留、导出或删除；不能静默丢失、转给新账户或代替用户开启同步。游客数据只有经显式归属与上传范围确认才可并入账户。

同平台布局、弹窗、错误/加载/离线/恢复与可访问性细节统一按 UI 规范；不另建一套设置系统。“自动记忆”的初始值/首次告知细节尚未确定，在 I/J/M 确认，不能以此改动已确定的记忆同步默认关闭。

## 4. 认证、会话与安全恢复

### 4.1 身份和凭据

- 邮箱验证注册、邮箱密码登录、Passkey、忘记密码、修改邮箱/认证方式、退出及注销都在首版正式范围。唯一身份映射防重复注册；注册/找回对外回应避免泄漏账户是否存在。邮箱规范化不能任意合并供应商的点号/别名；新邮箱验证完成后只更新身份，不改变 `user_id`。
- 密码绝不明文存储，采用经审查库的 Argon2id、安全随机盐和版本化参数。参数在 2 GB VPS 上测量并限制同时哈希数，不用降低安全性代替限流。[OWASP 密码存储指南](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html)
- 邮箱验证/恢复 challenge 只存安全验证材料，绑定用途、目标身份与请求；一次性消费、有有效期、最大尝试次数、重发间隔及地址/账户/IP/全局发送限流。短验证码不能仅靠无密钥快速哈希抵御离线枚举，使用成熟方案。并发消费、过期、用途交叉与旧码重用必须失败。[OWASP 找回密码指南](https://cheatsheetseries.owasp.org/cheatsheets/Forgot_Password_Cheat_Sheet.html)
- Passkey 使用成熟 WebAuthn/FIDO 库和平台 API；服务端验证 RP ID、origin、一次性 challenge、签名及用户验证策略，保存公钥与必要计数/元数据，不保存私钥。Windows/iOS 域名关联与实际原生调用需实施验证，不把计数器单一信号当作同步 Passkey 的绝对克隆判断。[W3C WebAuthn](https://www.w3.org/TR/webauthn-3/)
- 改邮箱、变更认证方式、云端记忆删除、注销等敏感操作需要重新认证；防止删除最后可用登录/恢复方式造成锁定。被盗恢复须能阻断被盗会话、轮换凭据、通知用户并记录安全事件；具体失去邮箱和全部 Passkey 时的核验流程需 I 设计审查，不能靠显示名称证明身份。
- 未来第三方 OAuth/OIDC 使用系统安全认证会话及 Authorization Code + PKCE；不在普通 WebView 收集第三方密码，不自创认证密码学。[RFC 8252](https://www.rfc-editor.org/rfc/rfc8252.html)

### 4.2 auth_sessions 与已登录设备

每次登录建立可独立撤销的 `auth_sessions`。显示会话/设备类型、登录时间、最近活动、当前设备和用户可修改名称；支持单独退出、退出其他所有设备、异常登录安全通知。随机安装标识可辅助展示/同步游标分流，但不是认证材料，也不限制新设备。名称、平台和安装 ID 属不可信展示资料。

刷新令牌安全生成、仅存安全摘要、按 token family 轮换，并原子检测旧令牌重放；合法并发刷新与重放的处理、丢失刷新响应后的恢复需要验证，不能无限放宽旧令牌。撤销确认后，服务器必须拒绝该会话后续所有受保护请求：选择 opaque token，或采用每次请求检查会话/撤销状态的短效 JWT；**只验证长寿命 JWT 签名不满足此约束**。[RFC 9700](https://www.rfc-editor.org/rfc/rfc9700.html)

账户令牌放平台安全存储，通过窄 DTO 暴露状态，不放聊天、记忆或普通同步载荷。退出本机会话立即停止账户网络任务、锁定对应缓存/索引/附件/配置视图；云端退出不能保证立即擦除离线设备下载的数据，也不等同于撤销另一套 Host 配对。账户与 Host 的两种撤销入口必须明确展示各自范围。

### 4.3 CLI公开客户端认证（正式方案，待实现）

桌面 `caidex login [--browser]` 用系统默认浏览器+Authorization Code+PKCE（S256）：一次性state/登录上下文、loopback-only临时回调、授权码防重放及client/redirect绑定、issuer/audience/归属校验，安全保存token后关闭监听；密码/Passkey只在官方HTTPS登录页接收，不进CLI或普通WebView。VPS/SSH无图形默认Device Authorization Grant，显式 `--device-code`可覆盖；官方验证页只登录已有账户，明确确认本次CLI请求，无注册入口。

Device流程遵RFC8628：秘密高熵device_code、短时随机user_code、HTTPS验证地址/期限/interval，按interval轮询pending、slow_down退避及拒绝/过期/取消/超时处理，一次性消费/client上下文绑定、防暴猜/限流及反诱骗提示；这不是旧设备批准新设备制度，不强制绑定或限制普通设备数。CLI是公开客户端，不内置长期Client Secret，成熟OAuth/OIDC库在I验证。浏览器/Device具体流程、参数与安全验收见[CLI规范第8节](CAIdex-CLI-完整交互与验收规范-V1.md#8-账户登录令牌与会话)。

两种流程共用同一规划中的官方账户后端，每次创建独立CLI auth_sessions，显示在GUI已登录设备并可单独撤销。建议access约10分钟/refresh约30天闲置且轮换，仅作I安全/可用性测试初值，未部署；撤销/重放/token family规则仍按4.2，不能只等access过期。Account Token与模型Key/Gateway/Host凭据分namespace、安全存储；Linux无Secret Service须明确授权Git外受保护明文文件。退出先处理本地待同步数据，撤销账户不删除项目或取消全部Host任务/独立配对；离线区分本地保存会话、服务器核验和同步未知状态。

CLI认证授权范围不能隐含Host执行权、Memory Sync启用或旧本地数据上传许可；ID Token不作数据API Access Token。token保存失败不得显示成功，尝试撤销本次新会话并报告实际结果；退出重试材料若含凭据仍只在独立安全存储，普通同步队列仅记公开操作状态。具体原子存储/撤销重试策略由I验证，不能借补交退出恢复已停账户正文传输。

CLI登录取消/到期须停止轮询并使本次回调上下文失效；迟到批准或令牌返回不能创建本机“已登录”状态、解除待确认停传意图或启动同步。若认证服务已签发本次会话，尝试仅撤销该会话，未确认则准确报告并将必要秘密留在安全存储，不误撤销已有其他有效会话。I建立公开客户端一次性授权/会话清理契约，P/R用CLI-17/19/21验证竞态；无需改动既有数据库实体、epoch或墓碑语义。

CLI两种登录共用独立的官方认证信任配置：验证issuer、client、资源audience及授权/Device/令牌端点和验证URL的归属，不仅判断HTTPS。模型Endpoint、项目配置及普通配置Profile不能重定向账户认证或接收Account Token；测试服务和生产服务的会话/安全存储隔离。I确定成熟库与域名注册，P/R按CLI-17/19/21/30实测错误目标、发现元数据及配置注入，失败不得建立登录或启动同步。沿用既有会话实体、默认关闭/继承及首次上传许可，不新增账户或同步架构。

## 5. PostgreSQL 与逻辑数据模型

采用版本化迁移；服务初期单实例，应用与数据库接口保留未来分离能力。以下为逻辑实体及最低不变量，具体表名/字段格式在 I 验证，但不能省略其语义。本节不是已经执行的建表 SQL。

| 实体 | 关键数据与关系 | 约束 / 归属 |
| --- | --- | --- |
| `users` | 不可变 `user_id`、账户状态、资料；记忆同步 `enabled/settings_version/cloud_epoch`、授权范围版本 | 邮箱不是主键；初始记忆同步关闭；注销/删除状态禁止普通数据访问 |
| `user_identities` | `identity_id → user_id`；邮箱或未来 OIDC issuer/subject、验证时间与状态 | 经定义规范化的登录身份唯一；修改不重建账户 |
| `auth_credentials` | `credential_id → user_id/identity_id`；密码 hash/算法参数，或 Passkey 公钥、credential ID 与 RP 信息 | 无明文密码/Passkey 私钥/模型 API Key；验证与恢复 challenge 可另表保存并保持一次性语义 |
| `auth_sessions` | `session_id → user_id`；刷新 family/摘要/轮换号/到期/撤销、登录及最近活动、展示平台 | 可独立撤销；展示安装 ID 不参与认证；refresh 消费与轮换原子化 |
| `security_events` | `event_id → user_id/session_id`；登录、恢复、撤销、敏感改动及告警结果 | 最小安全审计，无密码、完整 token 或记忆正文；保留与注销策略明确 |
| `projects` | `project_id → owner_user_id`；私有项目资料与授权版本 | 默认私有；不是 Host 文件权限或 Git 凭据授权 |
| `project_members` | `project_id + user_id`、显式角色/授予者/生效/撤销/授权版本 | 所有者及明确授权成员决定读写；撤销后服务器拒绝后续访问 |
| `conversations` | `conversation_id → owner_user_id`、可选项目、类型/分支/模型元数据、版本/状态 | 普通 Chat 与 Codex 线程仅显式关联，不把 Runtime 事件作为 Chat 正文 |
| `messages` | `message_id → conversation`；不可变正文版本、角色、时间、完成/中断状态、分支/附件引用 | 编辑产生新版本/分支；只有授权数据同步，凭据和敏感 Provider carrier 不自动上传 |
| `memories` | `memory_id`、归属账户、个人/项目 scope、可选项目、当前 revision、有效状态/隐私/时间 | 归属不依赖 Provider；项目所有者和成员 ACL 同时约束访问；隐私与同步选择独立 |
| `memory_sources` | 来源 ID、归属/scope、`revision_id`、Chat 引用或 Git commit/文件 hash/执行证据、可信类型/验证结果 | 跨租户/跨未授权项目引用禁止；不默认上传文件/网页/完整 journal；来源失效可追踪 |
| `memory_revisions` | `revision_id → memory_id`、父/base revision、内容/类别、作者、证据、有效期、取代关系 | 版本不可变；AI 候选不直接覆盖重要决定；冲突保留双方供纠正 |
| `memory_embeddings` | `revision_id + embedding_space_id`、Provider/model/revision、维度、距离度量、状态/向量 | 相同维度也不代表相同向量空间；不兼容版本不能混算；索引只含授权有效 revision |
| `memory_jobs` | 归属/scope、来源/base revision、工作类型、授权执行端引用、幂等键、状态/租约/重试/取消 | 保存编排与安全结果，不保存模型 Key；执行端离线等待；提交重验版本/权限/同步状态 |
| `sync_events` | 归属/scope、服务器单调序号、operation ID、实体/revision/epoch、事件类别与最少载荷 | 按范围增量；禁止携带秘密；提交与数据变更同一事务，不靠客户端时钟排序 |
| `sync_cursors` | 账户、会话/同步实例、scope、epoch、已确认序号与 schema/protocol version | 安装 ID 只分流；过期/失效 cursor 强制重建，不跳过删除屏障 |
| `deletion_tombstones` | 归属/项目、实体类型/ID、删除 revision/序号/epoch、回收屏障 | 独立于被删除正文；旧请求/任务/设备不能重新创建已删除实体 |

每条个人数据拥有明确 `user_id`，项目数据另有 `project_id` 与显式 ACL；作者、执行端和所有者不是同一概念。关联外键/唯一键携带必要 tenant/scope，防止 A 的来源链接到 B 的消息或项目。附件实体可独立建表/文件存储，但必须保留相同归属、版本、权限、删除和同步规则，不能只凭不可猜 URL 访问。

应用数据库角色不得是 superuser、`BYPASSRLS` 或表所有者，迁移/运维与普通服务角色分离；对保护表启用 RLS，按需 FORCE，默认拒绝未设置合法上下文的访问。RLS 是额外边界，API 仍校验认证与 ACL；限制危险权限及 security-definer 函数，不能把 RLS 当成绕过应用认证的理由。[PostgreSQL RLS 文档](https://www.postgresql.org/docs/current/ddl-rowsecurity.html)

账户上下文只能由服务器从真实已认证会话导出，不信任请求中的 `user_id`；在事务内绑定，连接池归还时不能残留上个租户上下文。普通查询、全文、pgvector、附件、后台任务、同步和导出使用同一策略；工作人员/任务不可凭“后台”获得跨用户遍历特权。向量查询在数据库内限制授权候选集，不能先查全体私人记忆再应用层过滤；未来 ANN 索引也不能弱化此约束。

Windows/iOS/Linux CLI的SQLite是本地缓存与本地记忆存储；Host SQLite是执行journal，两类逻辑分离。各端迁移、加密/OS 权限选择与云端 schema 各自版本化，共享语义契约，不强求物理表完全相同。

共享 API 契约按版本发布，区分认证/会话、项目权限、Chat、记忆管理、同步控制与数据通道；输入/分页/附件大小有界，错误安全分类，不返回第三方原始秘密。数据接口携带 scope/revision、同步接口另带 settings version/epoch/cursor 与 operation ID；控制与幂等结果表达“已确认、冲突、拒绝、待处理”，不把网络超时视为明确失败。具体路由/类型留 I 确定，但原子关闭、删除与权限不变量不能被客户端/服务端各自解释。

## 6. CAIdex Memory 数据契约与整合流程

### 6.1 五种数据分别管理

| 类型 | 用途与真源 | 长期记忆处理 |
| --- | --- | --- |
| 个人长期记忆 | 本账户明确决定、偏好等经过验证的长期资料 | 不向其他用户或项目自动扩散 |
| 项目长期记忆 | 有权限项目的决定、约束及事实 | 项目隔离；Git、源码和真实测试结果优先于旧 AI 记忆 |
| 原始 Chat 历史 | 原始对话、分支、附件及完成/中断轮次 | 独立 Chat 同步开关；可作授权来源，不等于全部长期记忆 |
| Codex 执行事件 / 任务状态 | 真实 Runtime + Host SQLite journal | 仅使用获授权的可核对证据引用/摘要；不是云端 Agent、完整 journal 上传或活动线程迁移 |
| 临时任务上下文 | 当前请求内预算、草稿与检索片段 | 不自动转为事实或长期记忆；须经过同一整合流程 |

模型无关 memory DTO 至少包含：稳定 ID、归属/scope、内容及结构化标签、来源引用/验证信息、类型、创建/有效时间、状态、revision/base/取代关系、隐私标记和允许同步范围。Provider 原生会话 ID、不透明推理/签名 carrier 或模型内部状态不作为此契约的身份/真源；未知数据标为未知，不能编造。

记忆区分**用户明确决定、用户偏好、项目文件证据、实际执行结果、AI 推断、已失效/被取代**。可信来源与推断分别展示；候选、已验证/有效、有争议、被取代、删除状态有明确转换与审计版本。模型分数只供排序，不能把“高置信”当可信验证。

### 6.2 自动整合与检索

候选提取 → 来源验证 → 去重 → 冲突分析 → 版本更新 → 按需检索。

1. 在授权范围读取来源，使用已有 ModelProvider 调用获授权的整合模型；输出仅作候选并进行结构校验，保留来源与 AI 推断标记。
2. 核对来源权限、内容 hash/版本、Git/文件或真实执行证据。外部网页、仓库文本和工具输出都是数据，不能变成系统指令、Host 权限或 Runtime 审批规则。
3. 仅在同账户/同授权 scope 内去重；语义相近不代表同一事实，不跨用户做内容匹配泄漏。重要决定变更须可信证据或用户明确确认，冲突/新旧决定保留 revision 与取代链，不能悄悄覆盖。
4. 由用户查看、修改、纠正、删除和导出个人/项目记忆及来源；删除不得由后台 AI 再次自动提取复活。导出遵循权限、选定范围和秘密排除。
5. 检索先账户/项目权限，再结构字段/精确关键词/有效状态和时间，按可用能力结合 pgvector 语义结果；只注入满足 Provider 授权与预算的片段，来源与可信类型随上下文呈现。

**自动记忆**控制提取、整合及使用长期记忆；关闭时停止自动任务与注入，但已有资料仍可由用户管理。**同步记忆**只控制 CAIdex 云端传输，二者独立。没有整合模型时可保存、编辑和基础检索，AI 任务暂停/等待；没有 Embedding 时同样回退结构/关键词检索，不使整个系统不可用。

Memory Engine 的共享逻辑独立于 Provider；模型调用发生在客户端或明确授权的 Host。云端可持久化/检索/编排获准同步范围内的任务，但同步关闭时，候选、整合/Embedding 作业及其来源状态留在本地，不能用云 job 元数据变相上传。执行端离线时等待其恢复，不能复制用户 Key 来后台执行。使用 Host 作记忆执行端也须有单独 Host 授权，登录账号不会自动授权 Host。

## 7. 跨模型、Embedding 与 Provider 隐私权限

Chat 模型、Memory 整合模型、Embedding 模型是三个角色。可以复用已配置模型，也可以单独选择整合模型；能力不可用则明确说明并回退。DeepSeek → GPT → Qwen 可读取相同授权 memory revision，更换 Chat 模型不重新生成长期记忆。此行为不保证正在执行的 Codex 线程跨 Provider 无损迁移：模型切换仍遵守 V3 的轮次边界及关联分支/新线程规则。

Embedding 空间标识包含 Provider/端点、模型与版本、维度、预处理版本和距离度量。更换空间产生新版本、按需重索引；查询只能匹配同空间，不将同维度不同模型混用。旧向量与新向量迁移期间依旧可基础检索；失效/删除 revision 的向量不得继续返回。初期使用权限过滤后的精确检索；未来 HNSW 的内存、查询计划/过滤及召回率必须负载验证。[pgvector 官方说明](https://github.com/pgvector/pgvector)

**CAIdex 云同步授权与向模型服务商发送记忆的授权完全独立**。Provider 记忆权限必须明确目标服务商/具体端点、用途（Chat 上下文、记忆整合、Embedding）、个人/项目范围与可发送类型；Key 已配置不表示允许发送记忆，关闭云同步也不表示外部 API 从不收到上下文。只限本地处理的数据在没有独立许可时不得发往远程端点；本地 Provider 更换为外部端点应重新核对授权。撤回授权后阻止后续发送/任务，不能宣称抹除服务商此前接收的数据。

用户自行配置模型 API Key；源码、Chat、记忆、来源、普通同步数据库/队列/日志/备份中禁止放 Key。调用仍使用执行端自己的 Broker，手机不得读取远程 Host 已存 Key。账户 token、EmailSender Key、模型 Key 三类秘密分别存放；供应商 Key 只服务端使用，用户模型 Key 不上传服务器。未来无人值守服务器模型调用须另行设计并获授权，不包含在本架构的默认权限中。

同步 DTO 采用允许字段与最小资料原则：正文/来源摘录/附件也可能含秘密，不能仅依赖字符串脱敏保证安全；已保存模型秘密与认证材料必须阻断，其他敏感资料需选范围与明确告知。现有 Runtime/Provider wire 保持完整真源，不能为“同步”破坏性脱敏，也不能因此直接全部上传。

## 8. 同步记忆：账户权威状态机

### 8.1 权威控制状态

服务端保存账户级 `enabled`（初始 false）、递增 `settings_version`、`cloud_epoch`、授权范围及删除状态；设备保存最近确认状态、版本和本地待提交关闭/开启操作。客户端视觉状态不能冒充服务器权威状态。

| 状态 / 动作 | 本机行为 | 服务器及其他设备 |
| --- | --- | --- |
| 从未开启 / 已确认关闭 | 本地 SQLite 生成/检索/跨模型使用/管理正常；记忆数据上传与下载停止 | 登录不能开启；拒绝整个账户的新记忆上传与下载，Chat 开关不变 |
| 首次申请开启 | 先认证、确认上传范围及 Provider 隐私边界；发送带 base version 的控制请求 | 验证会话/ACL/范围后原子更新权威状态与版本；未确认前不传记忆载荷 |
| 已确认开启 | 在授权范围按 cursor/outbox 同步，保存 operation ID/base revision/epoch | 每次上传、下载及派生结果提交重验状态、版本/epoch、会话与项目权限 |
| 在线关闭 A | 立即暂停本机记忆数据传输，提交“停止且保留” | 原子关闭并递增版本；确认点之后拒绝全账户新的记忆上传/下载，保留既有云端正文 |
| 离线关闭 A/B | **立即阻止本机上传与下载**、冻结记忆队列；显示“等待服务器确认关闭”，持久化控制请求 | 服务端收到前不能保证其他设备停止；重连优先确认关闭/删除控制，再处理任何数据队列 |
| 关闭 B / 删除处理中 | 重新认证、确认本地保存/选择；不等待清理完成才停止本机同步 | 先关闭并设删除/epoch 屏障，再幂等清理云端长期记忆；显示实际进度，不误报全部副本已抹除 |
| 已关闭 / 云端已删 | 保留的本地副本标为本地保留、脱离旧云 epoch；可本机使用 | tombstone/epoch 拒绝旧数据重试；不删除独立 Chat 或 Host journal |
| 重新申请开启 | 对保留云端、各设备本地差异及删除记录显式选择/合并；不直接覆盖 | 以最新 settings version/epoch 重新授权；旧 cursor 失效时重建；选定数据经冲突检测后才提交 |
| 状态冲突 / 旧客户端 | 保留本地数据，显示冲突或升级需要，不自作主张反复开启 | CAS 拒绝过期控制/数据请求；返回最新安全状态，必要时强制协议升级 |

控制请求幂等，使用 base settings version 的条件更新，不能靠设备时钟“最后写入胜出”。关闭确认必须与写入/下载授权形成明确事务顺序：确认点之后，新写入、旧排队任务提交、重试和新的下载页/流块均被拒绝；此前已下载字节无法撤回。每个请求携带版本并不够，服务端还须原子复核当前状态与项目授权，避免“先检查、后关闭、最后写入”的竞态。

不登录只能本地工作。关闭状态允许最少的认证控制面操作（查询开关/删除进度、提交关闭或删除），不传记忆正文；普通增量/检索下载无例外。此时本地导出正常，但不能通过云端 export API 暗中下载记忆正文。关闭期间保留云端记忆的导出流程在 I 审查；如需下载正文，应遵守已确定的开启/授权流程，不能自行增加绕过关闭的特许下载。

### CLI登录继承与首次上传许可

CLI不维护另一套独立默认开关，重新安装/登录/换设备先读取同一账户enabled/settings_version/cloud_epoch/授权范围；既有Enabled/Disabled直接继承，新账户仍默认false。启用状态未知或离线首次登录不冲刷旧队列。Windows开启后CLI继承Enabled，iOS关闭后CLI继承Disabled，CLI sync on/off同样改变全账户权威状态。

继承Enabled与这台设备首次上传许可分别记录：历史匿名、其他账户或未选范围的记忆不能自动改归属/上传，确认后才进入当前账户授权outbox。Linux本地SQLite按OS用户/user_id/项目隔离，登出原账户缓存不能作为游客暴露，纯本地跨模型记忆仍可工作。CLI关闭也按既定A保留/B删除、离线立即停传/待确认、CAS/epoch/tombstone和来源屏障；B须重认证，本地保留与其他设备影响明确。Chat同步/自动记忆/Provider外发权限独立，不上传Host journal/Key。详见[CLI记忆规则](CAIdex-CLI-完整交互与验收规范-V1.md#9-本地记忆与账户级同步)。

重新登录时保留本机未确认的关闭意图：权威状态仍Enabled也不能冲刷该设备旧队列，先提交关闭或明确处理CAS冲突。本地归属/上传许可不是独立记忆同步开关；服务器enabled/settings_version/cloud_epoch仍是唯一账户权威。此补充沿用8.1状态机，不改数据库实体、epoch或删除墓碑设计，实施断言对应CLI-24/26/32。

### 8.2 项目范围与多端一致性

账户开关约束该已认证 user_id 的所有设备、请求和记忆作业；授权某个项目或选择模型均不自动开启。对显式授权成员操作他人所有的项目记忆，须同时核对请求账户状态、数据所有者授权的云范围和项目 ACL；删除/权限撤销屏障不能被另一成员绕过。关闭个人账户同步不等同于撤销其他成员的项目权限；所有者仅停止同步后对其他已授权账户既有云端项目记忆的影响、具体多人写入角色及项目级范围交互在 I 明确并测试，影响产品行为时先确认，不能削弱个人隔离与账户级停止行为。

恢复联网先核对服务器控制状态/epoch、会话有效性和权限，再同步载荷。服务器故障或认证失效时继续保存隔离本地数据并提示，不能向另一个账户/端点自动转存。记忆同步与 Chat 同步的 outbox、cursor、错误和重试状态分别记录。

## 9. 冲突、删除、退出和升级

- 上传至少携带账户/scope、实体 ID、operation ID、base revision、settings version/epoch 与 payload hash；服务器不信任客户端 owner。数据变更、事件与幂等结果同事务落盘；重复同 ID/同载荷返回同一结果，同 ID/不同载荷拒绝。网络超时查询提交结果，不重造 ID 回避幂等。
- 离线多端修改使用 revision 父关系与冲突副本，保留双方来源；重要事实不能按客户端时间粗暴覆盖。去重在授权 scope 内以稳定 ID/来源 hash 等证据为基础，AI 近似匹配只给候选。Chat 保留不可变消息/并发分支，同步完成和中断轮次，草稿/临时上下文按独立契约。
- 用户删除记忆先使其不可检索，取消相关 job，删除/失效正文、专属来源摘录、revision、embedding 以及事件/队列中的敏感载荷，保留最少 tombstone/epoch 防复活。来源指向原 Chat 不表示删除 Chat；账户注销另有覆盖范围。旧来源不得自动重新提取同一已删记忆，用户明确重新创建才进入新授权流程。
- A“停止且保留”保留此前云端资料，不宣称删除；B“停止并删除”改变云 epoch，冻结旧 outbox/作业，删除完成报告不包括离线设备即时擦除或已过期前的本机备份。其他设备连接后获删除指令，处理对应本地副本；用户选择保留的副本脱离云关联，不能老设备恢复后自动重新上传。
- tombstone 不能在一个任意天数后删掉就允许所有旧客户端写入。回收须有 epoch/过期 cursor 拒绝及强制 snapshot/rebase 屏障；不同步期间的删除控制记录仍须可恢复。新 ID/旧内容的自动重提取也需来源删除标记/授权限制，不能仅防相同 ID 重放。
- 本地 SQLite 的 DB/搜索索引/附件/outbox/草稿按游客或 `user_id` 隔离，应用不能让新账户看到上个账户的缓存或模型配置/Key 权限。留存在同一 OS 用户下的数据保护强度须如实说明，不能声称阻止本机管理员。账户退出先处理未同步资料，再停止任务、清理内存状态并锁定原账户视图；不误删项目文件/Host journal 或自动撤销独立 Host 配对。
- 权限撤销、账号注销和会话撤销在服务器生效后拒绝后续请求，不能远程保证抹除离线副本。注销先重新认证/告知与可选导出、停发和作业取消、撤销全会话，再删除相关账户资料及其专属附件/记忆/Chat；共享项目关联按显式授权及归属处理，不能连带删除其他用户私有资料。必要安全记录最小化和备份期限需明确。
- 客户端和服务器协议/schema 版本化；本地及 PostgreSQL 迁移验证旧库、未同步队列、回滚/失败保护和磁盘不足。无法安全兼容的旧客户端拒绝云端写入并提示升级，保留本地内容，不丢弃消息/墓碑或悄悄降级成旧协议。

## 10. EmailSender 与免费事务邮件

## 11. 部署、监控与本机备份

### 11.1 初期资源与运营门槛

中国大陆 2 核 CPU / 2 GB RAM / 50 GB VPS 用于早期开发和小规模内测的官方账户、PostgreSQL/pgvector、HTTPS API、轻量检索及邮件任务。单实例应用与数据库即可，不需要 GPU，不运行大型本地语言模型，不强制 Redis、独立向量库、Kubernetes 或微服务集群。将应用/数据库、邮件 API、模型端点的网络和证书验证分别排查。

实施时建立并测量 CPU/RSS、系统可用内存、PostgreSQL buffers/每查询 work memory/连接数、连接池上限与排队、密码哈希并发、作业并发、磁盘/WAL/附件/向量/备份增长、p50/p95/p99、错误率和拒绝/超时。数据库连接不随设备数无限增长；限制单请求/页/附件/队列大小，磁盘不足先拒绝新写入并保护已有数据。精确检索与必要普通索引先行，HNSW 等高内存索引按负载报告再选择。

测试数据规模、并发、模型维度、资源分配及 SLO 在实际压测前登记，再根据测量给出支持范围；**不承诺固定用户容量**。更高配 VPS、独立 PostgreSQL 等是同架构扩展，不换临时数据库/同步协议。公开服务前另行核查中国大陆部署的备案、数据保护、隐私告知及跨境处理义务，结合实际主体、域名、邮件/模型供应商和数据流审查；本文不作已合规结论。本次不部署或购买服务。

### 11.2 明确不做异地备份

只保留 VPS 本机定期 PostgreSQL 备份、有限版本保留、完整性检查、本机恢复演练和磁盘监控；用户可手动导出 Chat/记忆，客户端保留各自 SQLite。**不部署独立异地备份服务器，不使用第三方对象存储自动备份，不要求额外购买云备份服务。**

备份需一致包含数据库、必须的附件、schema 版本及可恢复的删除/控制/撤销状态；任务定期校验能读取与恢复，不只检查文件存在。保留周期、最大空间与已删除资料何时从旧本机备份淘汰需明确展示，删除报告不假装备份已即时净化；恢复窗口/RPO/RTO 由演练给出。

恢复先隔离，校验迁移和最新可用删除账本/epoch/关闭状态；作废旧会话/同步世代，避免恢复旧 refresh 或重新发布已删数据。如果最新控制/删除记录丢失、仅旧快照存活，不能虚称知道快照之后的全部操作；应暂停旧资料发布，明确恢复点/潜在丢失并核实删除约束后恢复服务。演练包含旧备份和未提交队列，不能靠“恢复 SQL 成功”通过。

**本机备份不等于异地灾难恢复。整台 VPS 或磁盘彻底损坏时，正式数据库和本机备份可能一起丢失。普通客户端 SQLite 缓存不是可靠的全量云端备份，不能保证任意服务器故障下完整恢复。** 未同步的纯本地记忆也可能随重装或设备丢失而消失，界面与导出提示必须如实告知。
