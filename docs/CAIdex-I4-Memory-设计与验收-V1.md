# I-4 Memory Engine：设计与验收 V1

2026-10-11：用户确认 I-3 独立审计通过，并明确授权下一阶段 I-4。用户确认自动记忆首次默认关闭。实施会话不认领独立审计。

目标：在 I-3 本地账户分区内实现个人/项目记忆、来源与不可变 revision、纠错与冲突、授权基础/语义检索；复用 ModelProvider/Router/Adapter/Broker，实现独立整合与 Embedding 角色、精确空间版本及 Provider 外发许可。

有限任务：版本化 SQLite 迁移；手工创建、查看、纠错、候选批准、删除及导出；来源新鲜度校验；CAS 冲突保留双方；删除来源墓碑防自动复活；自动开关与本地任务等待/取消/重启未知终态；按账户/项目/隐私授权检索；Embedding 契约和显式兼容端点；普通 Chat 有界记忆注入；合成模型/实际本地来源的复现及三平台精确 CI。

非目标：I-5 Chat 同步、I-6 Memory 同步、I-7 生产运维、正式 GUI/CLI、生产邮件/部署、商业模型与真实用户 Key、iOS 安装验收。项目本地授权不代云 ACL；Host 离线不能隐式转用客户端 Key 或云执行。本轮不新增 Host RPC 或权限，不修改固定 Codex 0.160.1 的工具/审批链。

依赖：I-1 数据定义与 RLS、I-2 身份、I-3 namespace/cache；Account/Memory/Cloud §§6–7 与 MEM-01～10；V3 I-4；固定 Facade/ModelProvider/Registry/Router/Gateway/Broker。旧 PostgreSQL 迁移与 I-3 schema 1 不修改，新本地 schema 2 事务迁移保留 Chat。

通过条件：无模型可手工保存/检索，任务明确等待；来源与 AI 推断类型可见；原始 Chat/文件/Git/执行证据保持区分，新鲜度失效不能检索为事实；纠错 CAS 不最后写入覆盖；账户/项目撤权在读取和异步提交前生效；自动关闭停止提取/注入但手工 CRUD 可用；删除清理正文/向量/独占来源，旧来源不能自动复活；不同整合/Embedding/Chat 模型独立，精确空间版本与 revision 不混用；Key 归属和外发许可各自检查，已知凭据不入记忆/导出/模型正文；撤销/删除/切换/取消拒迟到结果，未知 POST 不重播；相关测试及精确 CI 通过，原始证据与限制可独立复现。

证据计划：定向 Rust 边界测试、合成 HTTP Embedding/整合及 Chat 注入复现；GitHub 三平台 workspace/fmt/Clippy、固定 Runtime/Host 及数据库认证回归。只本地静态/格式/差异检查，构建前检查磁盘，不清理有效缓存。只读独立审计前封存精确源码 SHA、CI 原始日志和试用步骤。
